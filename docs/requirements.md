# 연간 업무 실적 평가 프로그램 요구사항

## 목적

미리 정해진 등수별 목표 점수에 맞춰 각 팀원의 업무별 평가 결과를 자동으로 산정한다.

## 확정된 규칙

- 한 사람은 1~10개 사업에 참여한다. 사업별 참여 비중은 미리 정해져 있으며, 사람별 합계는 100%다. 참여 비중은 고정 입력값으로, 목표 점수를 맞추기 위해 변경하지 않는다.
- 각 사람이 참여하는 사업마다 서로 다른 업무가 4개 있다. 업무 가중치는 10%, 20%, 30%, 40%이며 합계는 100%다. 사업별로 각각 등급을 부여하므로, 두 사업에 참여하면 총 8개의 업무 등급을 정한다.
- **사업 점수**는 각 업무 점수에 해당 업무 가중치를 곱해 합산한 값이다.
- **개인 최종 점수**는 각 사업 점수에 해당 사업의 참여 비중을 곱해 합산한 값이다.
- **개인 목표 점수**는 평가 인원수에 해당하는 목표 점수표에서 그 사람의 등수로 조회한다. 등수는 사용자가 각 사람의 `rank`에 직접 입력하며, 프로그램이 순위를 정하지 않는다. `people` 목록에 적힌 순서는 등수가 아니다.
- 목표 평균과 표준편차는 별도로 입력하지 않는다. 팀 평균과 표준편차를 계산할 때는 평가 대상자별 최종 점수를 하나씩 사용한다.

## 업무 등급과 배점의 현재 가정

- 업무별로 S·A·B·C·D·E 중 하나의 등급을 배정하고 점수로 환산한다.
- 현재 가정한 배점은 **S=100, A=90, B=80, C=70, D=60, E=50**이다. 배점은 추후 달라질 수 있으며, 영구 확정된 기준으로 취급하지 않는다.
- 업무 가중치와 적용 배점표는 계산 조건이며, 탐색 대상은 사업별 업무 등급이다. 입력파일에는 업무 가중치, 등급 배점표, 개인별 목표 점수를 필수로 기재하지 않는다. 개인 목표 점수는 적용할 목표 점수표에서 조회한다.

## 목표 점수표

### 기본값과 적용 우선순위

- 아래의 2~15명 목표 점수표를 프로그램에 기본으로 내장한다. 기본값을 사용하려면 입력파일에 목표 점수표를 적지 않아도 된다.
- 입력파일에 `목표점수표:`를 별도로 기재하면, 입력파일에 기재한 목표 점수표를 내장 기본값보다 우선하여 적용한다.
- 점수 목록은 1등부터 N등까지의 순서다. 평가 대상자의 수로 해당 표를 선택하고, 입력한 등수로 개인 목표 점수를 조회한다.
- 앞서 논의한 별도 기준 파일 관리 방식 대신, **프로그램 내장 기본값과 입력파일의 선택적 지정** 방식으로 정리한다.

### 목표점수표 탭

- UI에 `목표점수표` 탭을 만들고, 인원수별 목표 점수를 조회·수정할 수 있도록 한다.
- 각 행에 인원수와 1등부터 N등까지의 목표 점수를 표시하고, 행 끝에 해당 목표 점수들의 **평균과 표준편차**를 함께 표시한다.
- 이 탭의 통계는 목표 점수로 계산한다. 결과 화면의 팀 요약은 산출 최종 점수로 계산한다.
- 탭에서 수정한 값의 적용 범위와 저장 방식, 입력파일 지정값과의 관계는 아직 정하지 않았다.

## YAML 입력 형식

다른 프로그램에서 사용하던 YAML을 최대한 그대로 사용할 수 있도록 `people` 목록 형식을 따른다. 각 사람은 `name`, `rank`, `allocations`로 작성한다. 아래 이름은 예시용 가상 인물이다.

```yaml
people:
  - name: 홍길동
    rank: 1
    allocations:
      사업1: 0.1
      사업2: 0.5
      사업3: 0.4
  - name: 김철수
    rank: 2
    allocations:
      사업1: 1.0
```

- `people`은 사람 목록이다. `name`은 이름, `rank`는 사용자가 지정한 등수(1등부터), `allocations`는 사업명을 키로 하는 참여 비중이다.
- 참여 비중은 백분율 숫자가 아닌 **0~1 범위의 비율**로 적는다. `0.1`은 10%, `0.5`는 50%, `1.0`은 100%다. 사람별 합계는 `1.0`이어야 한다. 기존의 `10`, `50`, `100` 같은 백분율 표기 대신 이 비율 표기를 사용한다.
- `rank`는 목록 순서와 독립적이다. 목록 위치나 이름의 숫자로 등수를 추정하지 않는다. 목표 점수 조회와 결과 표시 순서는 `rank`를 따른다.
- 예시의 평가 인원은 2명이므로 내장된 2명 표를 사용한다. 홍길동의 목표는 94점, 김철수의 목표는 87점이다.
- 사람과 사업에 별도 ID를 두지 않는다. 동명이인은 사용자가 `김예시1`, `김예시2`처럼 구분한다. 이름 끝 숫자는 등수가 아니다.
- 사업명은 사람별 사업 구분과 출력에 사용한다. 서로 다른 사람에게 같은 사업명이 있어도 업무 등급이나 사업 점수를 공유하지 않고 각각 계산한다. 사람 간에는 최종 점수가 입력 등수 순서를 지켜야 한다는 조건을 적용한다.
- 사업명에 공백을 쓸 수 있다. `: `나 ` #`처럼 YAML에서 특별한 의미가 있는 부분이 들어간 이름은 따옴표로 감싼다.
- 업무명과 업무 가중치는 입력하지 않는다. 프로그램은 사업마다 고정된 `업무10`, `업무20`, `업무30`, `업무40`을 사용하고, 결과도 이 이름으로 구분한다.

내장 기본값을 사용하면 `목표점수표` 항목은 생략한다. 목표 점수를 별도로 지정하려면 같은 YAML 문서의 최상위에 아래 항목을 추가한다. `people` 목록의 형식은 그대로 유지한다.

```yaml
목표점수표:
  2: [94, 87]
  3: [95, 90, 85]
```

이 항목을 기재하면 입력파일의 목표 점수표를 내장 기본값보다 우선 적용한다.

## 입력 검증

- `people` 목록의 `name` 중복, 같은 사람의 `allocations` 합계가 `1.0`이 아닌 경우, `rank` 중복을 오류로 처리한다. 오류가 있으면 점수 계산을 시작하지 않고 문제가 된 이름과 값을 알린다.
- 사람 이름 중복은 YAML을 읽고 `people` 목록 전체의 `name`을 비교하여 확인한다. 목록의 서로 다른 항목에 같은 이름이 있어도 중복으로 처리한다.
- 추가 검사 제안: 같은 사람의 `allocations` 아래 사업명 중복, `rank` 범위(1~N), 해당 인원수의 목표 점수표 누락 또는 점수 개수 불일치. YAML 매핑의 중복 키가 조용히 덮어써지지 않도록 읽는 단계에서 검사를 고려한다.

## 점수 산정 기준

- **필수 조건:** 산출된 개인 최종 점수는 입력 등수에 따라 `1등 > 2등 > … > N등`이어야 한다. 동점이나 순위 역전이 있는 조합은 유효한 결과로 인정하지 않는다.
- **최적화 목표:** 순위를 지키는 조합 중 개인별 절대 오차(`|산출 최종 점수 − 목표 점수|`)의 최댓값을 최소화한다. 목표 점수와 소수점까지 일치할 필요는 없다.
- **동일한 최적 해의 선택 기준:** 최대 개인 오차가 같은 최적 해가 여러 개면, 사람별로 **참여 비중이 높은 사업의 총점**이 높은 해를 우선한다. 그 사업 안에서는 **업무 가중치가 높은 업무의 등급 점수**가 높은 해를 우선한다. 업무 우선순위는 `업무40 > 업무30 > 업무20 > 업무10`이다.
- 선택 기준은 **사업 우선** 방식이다. 사업 참여 비중과 업무 가중치를 곱한 개별 업무의 합성 가중치 순서로 비교하는 방식은 사용하지 않는다. 이 기준을 위해 입력 등수 조건을 위반하거나 최소 최대 오차를 늘리지 않는다.

## 결과 화면

- 왼쪽에는 사람 목록을 입력 등수순으로 표시하고, 이름 옆에 산출 최종 점수를 보여준다. 산출 점수를 기준으로 등수를 다시 매기지 않는다.
- 사람을 선택하면 오른쪽에 사업별 업무 점수 표를 표시한다. 한 행은 한 사업이며, 업무 열은 `업무40`, `업무30`, `업무20`, `업무10` 순서다.
- 팀 요약에는 모든 평가 대상자의 **산출 최종 점수**로 계산한 평균과 표준편차를 표시한다.
- 화면 구성 제안: 사업명 옆에 참여 비중을 표시하고, 상세 화면 상단에 개인 목표 점수와 산출 점수를 나란히 표시한다. 등급제로 결정되면 각 업무 칸에 등급과 환산 점수를 함께 표시하는 방안을 검토한다.

## 미결 사항

- 참여 비중이 같은 사업들의 우선순위, 사업·업무 우선 기준까지 같은 해의 최종 선택 기준은 어떻게 정하는가? 정확한 목표 일치가 불가능하여 사람별 우선 기준이 충돌할 때의 사람 간 비교 순서도 정하지 않았다.
- 현재 가정 배점에서 변경할 최종 배점표와 변경 관리 방식, 소수 목표 점수 지원 여부와 계산 시 반올림 방식은 어떻게 정하는가?
- 허용된 점수나 등급으로 입력 등수 순서를 지키는 조합이 없다면 화면에 어떻게 안내하는가?
- 목표점수표 탭과 결과 화면에 표시할 표준편차는 모집단과 표본 중 어느 방식으로 계산하는가? 모표준편차 사용을 추천했지만 사용자가 아직 확정하지 않았다. 통계의 표시 자릿수와 반올림 방식도 정하지 않았다.
- 입력파일의 `목표점수표`에 일부 인원수만 기재했을 때, 빠진 인원수는 내장 기본값으로 보완할지 아니면 지정한 표에 없다는 오류로 처리할지 정하지 않았다. 빈 표나 잘못된 값의 처리, 내장표 범위 밖 인원수의 지원 여부도 정하지 않았다.
- 목표점수표 탭에서 수정한 값의 적용 범위와 저장 방식, 입력파일 지정값과의 관계는 어떻게 정하는가?
