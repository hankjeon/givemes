# 세션 인수인계

## 현재 상태

- 채점 요구사항을 논의 중이다. 프로그램 구현은 시작하지 않았다.
- 2~15명 목표 점수표를 프로그램에 기본으로 내장하고, YAML 입력파일에 `목표점수표:`를 별도로 기재하면 입력파일의 표를 우선 적용하기로 했다. 내장 기본값을 사용할 때 입력파일에는 사람별 이름·등수·사업 참여 비중만 적으면 된다. 별도 기준 파일 관리 방식 대신 이 방식으로 정리했다.
- 입력 형식은 기존 프로그램과 호환하기 위해 `people` 목록을 사용하며, 각 항목은 `name`, `rank`, `allocations`로 작성한다. `allocations`는 사업명→참여 비율이며 `0.1=10%`, 사람별 합계 `1.0`이다. `rank`는 사용자가 명시적으로 추가하며 목록 순서로 추정하지 않는다. 이전의 `사람`/`등수`/`사업` 키와 백분율 숫자 표기 대신 이 형식을 사용한다. 목표 점수 조회와 결과 표시 순서는 `rank`를 따른다.
- 전체 내장 기본값과 입력 예시, 필수 오류 검사는 [요구사항 문서](requirements.md)에 정리했다. 13명 표의 8등은 98점이 아닌 **89점**으로 정정됐다. 내장표 평균은 2명일 때 90.5점, 3~15명일 때 모두 90점이다.
- UI에 `목표점수표` 탭을 두고 인원수별 점수를 조회·수정하며, 각 행 끝에 목표 점수의 평균과 표준편차를 표시한다. 탭의 수정값 적용·저장 방식과 입력파일 지정값과의 관계는 미결이다.
- 산출 점수는 입력 등수 순서를 반드시 지켜야 하며, 유효한 조합 중 최대 개인 오차가 가장 작은 조합을 우선한다. 결과는 등수순 사람 목록과 사업별 업무 표로 표시하고, 팀 평균과 표준편차도 표시한다.
- 최대 개인 오차가 같은 최적 해가 여러 개면 **사업 우선**으로 선택한다. 참여 비중이 높은 사업의 총점을 먼저 높이고, 그 사업 안에서 가중치가 높은 업무의 등급 점수를 우선한다(`업무40 > 업무30 > 업무20 > 업무10`). 사업 참여 비중×업무 가중치의 합성 가중치 순서로 고르는 방식은 사용하지 않는다. 입력 등수와 최소 최대 오차 조건이 이 선택 기준보다 우선한다.
- 업무는 사업마다 4개씩 별도로 평가한다(두 사업이면 총 8개 등급). 현재는 S=100, A=90, B=80, C=70, D=60, E=50으로 가정하며 배점은 추후 바뀔 수 있다. 사업 참여 비중과 업무 가중치는 고정하고 업무별 등급만 탐색한다. 다른 사람의 같은 사업명과는 점수나 등급을 공유하지 않는다.

## 다음에 이어갈 질문

사업 우선 선택 기준은 정해졌다. 참여 비중이 같은 사업들의 비교 순서와 모든 우선 기준까지 같은 해의 최종 선택 기준, 정확한 목표 일치가 불가능해 사람별 우선 기준이 충돌하는 경우의 사람 간 비교 순서는 아직 미결이다. 목표 점수와의 정확한 일치는 필요 없지만, 입력 등수 순서를 지키는 조합이 없을 때의 안내 방식도 아직 정하지 않았다.

추가 미결 사항은 표준편차 방식(모집단/표본)과 통계 표시 자릿수, 입력파일에서 일부 인원수만 지정했을 때의 보완/오류 규칙, 빈 표·잘못된 값·내장표 범위 밖 인원수의 처리다. 요구사항 문서의 모표준편차 수치는 확인용이며 계산 방식이 확정됐다는 뜻은 아니다.

답을 확인한 뒤 요구사항 문서를 갱신한다. 이번 변경은 합의 내용을 문서에 기록하는 작업이며 앱 구현은 하지 않았다. 미결 기준은 임의로 확정하지 않으며, 논의에 대한 동의를 구현 승인으로 해석하지 않는다.
